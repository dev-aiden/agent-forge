# Kitroom 사용법

Kitroom은 Claude Code, Codex CLI 같은 AI 코딩 도구의 **에이전트 · 스킬 · 규칙 · MCP 서버**를 한 화면에서 만들고, 여러 도구에 한 번에 적용하는 무료 오픈소스 데스크톱 앱입니다 (macOS · Windows · Linux).

- 같은 "코드 리뷰어 에이전트"를 도구마다 다른 형식으로 두 번 만들 필요가 없습니다. 한 번 만들면 고른 도구들의 형식에 맞춰 써 줍니다.
- 지금 어떤 설정이 깔려 있는지 **한눈에** 보여 줍니다.
- 설치된 AI 코딩 도구를 앱 안의 **터미널 탭**에서 바로 실행할 수 있습니다.

> English: [docs/usage.md](../usage.md)

### 안전장치

| 걱정 | 실제 동작 |
|---|---|
| 내 AI 구독·API 키를 쓰나요? | **아니요.** 앱은 AI를 직접 부르지 않습니다. API 키 입력 칸도 없습니다. AI는 각 도구가 원래대로 내 구독으로 돌립니다. |
| 로그인 정보를 가져가나요? | **아니요.** 각 도구의 로그인·토큰 파일은 읽지도 복사하지도 않습니다. |
| 인터넷으로 무언가 보내나요? | **아니요.** 유일한 네트워크 요청은 "새 버전 확인"(GitHub에 최신 버전 번호만 물어봄)이고, 설정에서 끌 수 있습니다. 계정·서버·사용 통계는 없습니다. |
| 내 설정 파일을 망가뜨리면? | 파일을 바꾸기 전에 **무엇이 바뀌는지 미리보기**를 보여 주고, 원본을 **백업**한 뒤에 씁니다. **되돌리기** 버튼으로 언제든 복원할 수 있습니다. |
| 미리보기 후에 내가 파일을 고쳤다면? | 적용할 때 다시 확인해서, 미리보기 이후 바뀐 파일이 있으면 **적용을 거부**합니다. 되돌리기도 내가 직접 고친 파일은 건드리지 않습니다. |

## 1. 준비물

- macOS(Apple Silicon 또는 Intel), Windows 10/11(64비트), Linux(x64) 중 하나
- 아래 AI 코딩 도구 중 **하나 이상**이 설치·로그인되어 있으면 좋습니다. 없어도 앱은 열리지만 볼 게 적습니다.
  - **Claude Code** (`claude`)
  - **Codex CLI** (`codex`)
  - GitHub Copilot CLI (`copilot`), Antigravity CLI (`agy`) — 보기만 지원 (7장 참고)
- MCP 템플릿을 쓰려면 Node.js(`npx`)가 필요합니다.

## 2. 설치

[GitHub Releases](https://github.com/dev-aiden/kitroom/releases/latest)에서 내 OS에 맞는 파일 하나를 받습니다.

| OS | 받을 파일 |
|---|---|
| macOS (Apple Silicon: M1 이후) | `kitroom-<버전>-mac-arm64.dmg` |
| macOS (Intel) | `kitroom-<버전>-mac-x64.dmg` |
| Windows | `kitroom-<버전>-win-x64.exe` |
| Linux | `kitroom-<버전>-linux-x86_64.AppImage` |

> 아직 코드 서명이 없어서 **처음 실행할 때 보안 경고가 뜹니다.** 아래대로 하면 열 수 있습니다.

### macOS

**Homebrew로 설치** (설치와 업데이트를 명령 한 줄로):

```bash
brew install --cask dev-aiden/tap/kitroom   # 설치
brew upgrade --cask kitroom                 # 나중에 업데이트
```

아직 코드 서명이 없어서 아래 2번의 경고는 Homebrew로 설치해도 뜰 수 있습니다.

**직접 받아서 설치:**

1. `.dmg`를 열고 **Kitroom**을 `응용 프로그램(Applications)` 폴더로 끌어 놓습니다.
2. 처음 열 때 **"손상되었기 때문에 열 수 없습니다"** 또는 **"확인되지 않은 개발자"** 경고가 뜨면, 터미널에서 한 번만 실행하세요:
   ```bash
   xattr -cr "/Applications/Kitroom.app"
   ```
   그다음 다시 열면 됩니다. (인터넷에서 받은 파일에 붙는 "격리 표시"를 지우는 명령입니다.)
3. 또는 `시스템 설정 → 개인정보 보호 및 보안` 아래쪽의 **"그래도 열기"**를 눌러도 됩니다.

> 내 Mac이 어떤 칩인지는 ` 메뉴 → 이 Mac에 관하여`의 "칩" 또는 "프로세서" 항목에서 볼 수 있습니다. "Apple M…"이면 arm64, "Intel"이면 x64 파일을 받으세요.

### Windows

1. `.exe`를 실행합니다.
2. **"Windows의 PC 보호"** 파란 창이 뜨면 **추가 정보 → 실행**을 누릅니다.
3. 설치 위치를 고르고 설치합니다.

### Linux

```bash
chmod +x kitroom-*.AppImage
./kitroom-*.AppImage
```

## 3. 5분 만에 시작하기

이미 Claude Code나 Codex를 쓰고 있다면 이 순서를 추천합니다.

1. **한눈에 보기**에서 지금 깔려 있는 설정을 확인합니다.
2. **에이전트 → `가져오기`**, **스킬 → `가져오기`**, **규칙 → `지금 쓰는 규칙으로 시작하기`**, **MCP → `지금 쓰는 서버 가져오기`** 를 차례로 누릅니다. 지금 쓰던 것들이 앱 목록에 들어옵니다.
3. 아무 화면에서나 `미리보기 후 적용`을 눌러 봅니다. **"이미 최신 상태"**가 나오면 준비 완료입니다. (가져오기만 해서는 도구 설정이 바뀌지 않습니다.)
4. 에이전트 화면에서 **`템플릿` → 코드 리뷰어 → `이 템플릿 사용`** → `에이전트 만들기` → `미리보기 후 적용` → `2개 적용`.
5. **터미널** 탭에서 `+ Claude Code`를 열고 `/agents`를 입력하면 `code-reviewer`가 보입니다. Codex에서도 같은 에이전트를 쓸 수 있습니다.
6. 마음에 안 들면 왼쪽 아래 **적용 기록 → `되돌리기`**.

처음 쓰는 도구라면 2번은 건너뛰고 템플릿부터 시작하면 됩니다.

## 4. 화면 구성

앱을 열면 위쪽에 메뉴가 있습니다.

```
Kitroom [한눈에 보기|에이전트|스킬|규칙|MCP|Claude 설정|터미널]  프로젝트 없음(전역만) [선택…]   ● 읽음  [새로고침] [설정]
```

| 메뉴 | 하는 일 |
|---|---|
| **한눈에 보기** | 도구별로 지금 깔려 있는 규칙·에이전트·스킬·MCP 서버를 보여 줍니다. 읽기만 합니다. |
| **에이전트** | 에이전트(서브에이전트)를 만들어 Claude Code·Codex에 적용합니다. |
| **스킬** | 스킬(`SKILL.md`)을 만들어 적용합니다. |
| **규칙** | 모든 도구가 읽는 최상위 지시문(`CLAUDE.md`, `AGENTS.md`)을 한 곳에서 고칩니다. |
| **MCP** | MCP 서버 목록을 한 곳에서 관리하고 적용합니다. |
| **Claude 설정** | Claude Code `settings.json`의 권한 규칙(허용·확인·거부)과 hooks를 관리합니다. Claude Code가 감지될 때만 보입니다. |
| **터미널** | 설치된 AI 코딩 도구나 셸을 앱 안 탭에서 실행합니다. |
| **프로젝트 [선택…]** | 특정 프로젝트 폴더를 고르면 그 프로젝트의 설정도 함께 보고, 그 프로젝트에만 쓸 수 있습니다. |
| **설정** | 언어(한국어/English), 테마(라이트/다크), 보여 줄 도구, 새 버전 확인을 고릅니다. |

오른쪽 위 초록 점(●)은 **설정 파일 감시 중**이라는 뜻입니다. 다른 곳에서 파일을 바꾸면 화면이 저절로 갱신됩니다.

## 5. 기본 흐름: 저장 → 미리보기 → 적용 → 되돌리기

에이전트·스킬·규칙·MCP 화면은 모두 같은 방식으로 동작합니다.

1. **저장** — 내용을 적고 `에이전트 만들기`(또는 `변경 저장`)를 누릅니다.
   이때는 Kitroom 안(`~/.kitroom`)에만 저장됩니다. **도구 설정은 아직 그대로**입니다.
2. **미리보기 후 적용** — 오른쪽 위 버튼을 누르면 `변경 사항 확인` 창이 뜹니다.
   - 어떤 파일이 `생성` / `수정` / `삭제`되는지
   - 파일마다 `변경 내용 보기`로 바뀌는 줄(초록 = 추가, 빨강 = 삭제)
   - 주의할 점(노란 안내 문구)
3. **N개 적용** — 확인했으면 누릅니다. 원본을 백업한 뒤 파일을 씁니다.
4. **되돌리기** — 왼쪽 아래 `적용 기록`에서 해당 기록의 `되돌리기`를 누르면 적용 전으로 돌아갑니다.

> 비밀값(토큰, 비밀번호 등)은 화면과 미리보기에서 항상 `••••`로 가려집니다.

### 적용 대상: 전역 vs 이 프로젝트

에이전트·스킬·규칙·MCP 화면 위쪽에 **적용 대상** 줄이 있습니다.

| 선택 | 쓰는 곳 | 언제 쓰나요 |
|---|---|---|
| **전역 (~)** | `~/.claude`, `~/.codex` 등 내 사용자 설정 | 어느 폴더에서든 쓰고 싶은 것 |
| **이 프로젝트** | 고른 프로젝트 폴더 안 (`.claude/`, `.codex/`, `.agents/`, `CLAUDE.md`, `AGENTS.md`, `.mcp.json`) | 그 프로젝트에서만 쓰고 싶은 것 |

- `이 프로젝트`는 위쪽 **프로젝트 [선택…]** 으로 폴더를 먼저 골라야 켜집니다.
- 전역과 프로젝트는 **목록이 따로** 관리됩니다. (전역에 만든 에이전트는 프로젝트 목록에 안 보이는 게 정상)
- 프로젝트용 원본은 프로젝트가 아니라 내 컴퓨터(`~/.kitroom/projects/`)에만 저장됩니다. 프로젝트 폴더에는 도구가 읽는 결과 파일만 생깁니다.

## 6. 화면별 사용법

### 6-1. 한눈에 보기

- 위쪽 탭에서 도구(Claude Code, Codex CLI …)를 고르면 그 도구의 **규칙 / 에이전트 / 스킬 / 명령 / MCP 서버**가 나옵니다. 명령은 Claude Code 커스텀 명령(`commands/*.md`)과 Codex 커스텀 프롬프트(`~/.codex/prompts/*.md`)입니다. [예전 명령을 스킬로 옮기기](#예전-명령을-스킬로-옮기기)를 참고하세요.
- 항목을 누르면 오른쪽에 내용과 파일 위치가 나옵니다.
- 배지 뜻:
  - `전역` / `프로젝트` / `로컬` — 어느 범위의 설정인지
  - `미확인 경로` — 도구의 공식 문서로 확인되지 않은 위치 (지금은 `~/.claude/commands`뿐. 공식 문서에는 프로젝트 폴더 `.claude/commands`만 나옵니다)
  - `claude.ai` — claude.ai에서 동기화된 스킬 (앱이 건드리지 않음)
- 검색 칸에 이름이나 설명 일부를 치면 걸러집니다.

### 6-2. 템플릿으로 시작하기

처음이라 무엇을 만들지 막막하면 **템플릿**부터 써 보세요. 에이전트·스킬·MCP 화면 목록 위의 `템플릿` 버튼(목록이 비어 있으면 `템플릿에서 시작하기`)을 누르면 미리 만들어 둔 예시가 나옵니다.

| 화면 | 들어 있는 템플릿 |
|---|---|
| 에이전트 | 코드 리뷰어, 테스트 작성, 디버거, 보안 점검, 리팩터링, 문서 작성 |
| 스킬 | 커밋 메시지, PR 설명, 변경 기록(CHANGELOG), 코드 설명 |
| 규칙 (`문단 추가`) | 한국어로 답하기, 작게 나눠 커밋, 끝났다고 하기 전에 확인, 위험한 명령 전에 확인 |
| MCP | Playwright(브라우저), Context7(라이브러리 문서), Memory(기억 저장) |

- 템플릿을 고르면 **입력란만 채워집니다.** 저장·적용은 평소처럼 직접 눌러야 합니다.
- 지시문은 영어로 되어 있습니다(AI가 가장 안정적으로 따릅니다). 그대로 써도 되고 고쳐도 됩니다.
- 같은 이름이 이미 있으면 `code-reviewer-2`처럼 이름 뒤에 번호가 붙습니다.
- 규칙 템플릿은 지금 규칙을 **덮어쓰지 않고 끝에 덧붙입니다.** 이미 들어 있는 문단은 다시 넣지 않습니다.
- MCP 템플릿은 Node.js(`npx`)가 필요합니다. 처음 실행할 때 패키지를 내려받느라 조금 걸릴 수 있습니다.

### 6-3. 에이전트

> **이미 Claude Code·Codex에 에이전트가 있다면 먼저 `가져오기`를 누르세요.** 앱이 모르는 에이전트와 같은 이름으로 만들면 적용할 때 충돌이 납니다.
> - 가져오면 앱 목록에 나타나고, 그다음부터 앱에서 고치고 적용할 수 있습니다.
> - 가져온 직후 `미리보기 후 적용`을 누르면 "이미 최신 상태"가 나와야 정상입니다. 무언가 바뀐다고 나오면 [이슈](https://github.com/dev-aiden/kitroom/issues)로 알려 주세요.
> - 앱 화면에 없는 설정(Claude Code의 `color`, `permissionMode`, Codex의 `model`, `sandbox_mode` 등)은 "그 밖의 설정"에 보이고, 고쳐도 그대로 유지됩니다.
> - 같은 이름이 두 도구에 있는데 내용이 다르면 Claude Code 쪽을 가져오고 알려 줍니다.
> - 파일 이름과 `name`이 다른 에이전트는 가져오지 않습니다 (적용하면 같은 에이전트가 두 개 생기므로). 파일 이름을 `name`과 같게 바꾼 뒤 다시 가져오세요.

1. `새로 만들기`를 누릅니다. (또는 `템플릿`에서 골라 시작합니다.)
2. 채울 것:
   - **이름**: 영문·숫자·`-`·`_` (예: `code-reviewer`). 파일 이름이 됩니다.
   - **설명**: 도구가 *언제* 이 에이전트를 쓰면 되는지 (예: "변경 사항에서 버그와 위험한 부분을 검토합니다")
   - **적용할 도구**: Claude Code, Codex CLI 중 체크
   - **모델 / 허용 도구**: Claude Code에만 적용. 비워도 됩니다.
   - **지시문**: 에이전트에게 줄 지시 (예: "당신은 꼼꼼한 코드 리뷰어입니다…")
3. `에이전트 만들기` → `미리보기 후 적용` → `N개 적용`

결과 파일:

| | 전역 | 프로젝트 |
|---|---|---|
| Claude Code | `~/.claude/agents/<이름>.md` | `<프로젝트>/.claude/agents/<이름>.md` |
| Codex CLI | `~/.codex/agents/<이름>.toml` | `<프로젝트>/.codex/agents/<이름>.toml` |

수정하려면 왼쪽 목록에서 고르고 고친 뒤 `변경 저장` → 다시 적용. 삭제는 `삭제` → 적용하면 도구에서도 지워집니다.

### 6-4. 스킬

에이전트와 같습니다. 본문은 `SKILL.md 내용` 칸에 씁니다. 칸이 두 개 더 있습니다.

- **이름으로 부를 때만 사용** — 도구가 알아서 이 스킬을 고르지 않고, `/이름`(Claude Code)이나 이름으로 부를 때(Codex)만 씁니다. Claude Code에는 `disable-model-invocation: true`로, Codex에는 스킬의 `agents/openai.yaml`에 `policy.allow_implicit_invocation: false`로 들어갑니다.
- **인자 힌트** — Claude Code만. `/이름`을 입력할 때 보이는 안내입니다. 예: `[issue-number]` (`argument-hint`)

| | 전역 | 프로젝트 |
|---|---|---|
| Claude Code | `~/.claude/skills/<이름>/SKILL.md` | `<프로젝트>/.claude/skills/<이름>/SKILL.md` |
| Codex CLI | `~/.agents/skills/<이름>/SKILL.md` | `<프로젝트>/.agents/skills/<이름>/SKILL.md` |

> 이름 `synced`는 Claude가 쓰는 폴더라 사용할 수 없습니다.

기존 스킬도 `가져오기`로 가져올 수 있습니다. 스킬 폴더 안의 다른 파일(`scripts/` 등)도 함께 가져와 그대로 유지합니다. 다만 아래 경우는 가져오지 않고 이유를 알려 줍니다.
- 이미지처럼 텍스트가 아닌 파일이 들어 있는 스킬
- 폴더 이름과 `name`이 다른 스킬 (적용하면 같은 스킬이 두 개 생기므로)
- Kitroom이 아직 그대로 유지할 수 없는 설정이 들어 있는 스킬 (예: Codex 스킬의 `license`, 알 수 없는 frontmatter 항목)
- 링크(심볼릭 링크) 파일이 들어 있거나, 파일이 너무 많거나 큰 스킬 (200개 / 20MB 초과)
- Codex 화면 설정 파일(`agents/openai.yaml`)이 있는 스킬
- 옛 위치(`~/.codex/skills`)에 있는 스킬
- claude.ai에서 동기화된 스킬(`~/.claude/skills/synced`)

#### 예전 명령을 스킬로 옮기기

Claude Code는 커스텀 명령을 스킬로 합쳤고, Codex는 커스텀 프롬프트 대신 스킬을 쓰라고 안내합니다. 내 스킬 아래 **예전 명령** 목록에 지금 범위의 명령이 나옵니다.

| | 전역 | 프로젝트 |
|---|---|---|
| Claude Code | `~/.claude/commands/*.md` | `<프로젝트>/.claude/commands/*.md` |
| Codex CLI | `~/.codex/prompts/*.md` | — |

`스킬로 옮기기`를 누르면 같은 이름·설정·내용으로 같은 도구용 Kitroom 스킬을 만듭니다. Codex 프롬프트는 예전처럼 이름으로 부를 때만 쓰는 스킬이 됩니다. 미리보기 후 적용하기 전까지 도구에는 바뀌는 것이 없습니다.

- **다음 적용 때 원래 파일 지우기** (기본은 꺼짐): 다음 미리보기에 명령 파일이 `삭제`로 나옵니다. 원본은 백업되고 `되돌리기`로 복구됩니다. 옮긴 뒤 파일을 고쳤거나, 스킬을 지웠거나, 스킬의 적용할 도구에서 그 도구를 뺐다면 지우지 않습니다. 이름이 같으면 명령보다 스킬이 우선하므로, Claude Code에서는 파일을 남겨 둬도 문제없습니다.
- 인자 자리표시(`$1`, `$ARGUMENTS`, `$NAME`)를 쓰는 프롬프트는 경고가 나옵니다. Codex 스킬은 이 값을 채워 주지 않으니 옮긴 뒤 내용을 확인하세요.
- 다음은 옮기지 않고 이유를 알려 줍니다: 하위 폴더에 있는 명령(`git/commit.md`)이나 스킬에 쓸 수 없는 이름, 같은 이름의 스킬이 이미 있는 명령, 스킬이 유지할 수 없는 frontmatter가 있는 명령.

### 6-5. 규칙 (최상위 지시문)

모든 도구가 대화 시작 때 읽는 지시문입니다. Claude Code는 `CLAUDE.md`, Codex는 `AGENTS.md`를 읽습니다.

1. 처음에는 `지금 쓰는 규칙으로 시작하기`를 누릅니다. 지금 쓰는 내용을 가져옵니다.
   - 두 도구의 내용이 다르면 Claude Code 쪽을 가져오고 알려 줍니다.
2. 고친 뒤 `변경 저장` → `미리보기 후 적용`. 고른 도구들에 **같은 글**이 써집니다.
3. `문단 추가`를 누르면 자주 쓰는 규칙 문단(한국어로 답하기 등)을 끝에 덧붙일 수 있습니다.
4. 더 이상 앱으로 관리하기 싫으면 `관리 중단` (도구 파일은 그대로 남습니다).

> Codex에서 `AGENTS.override.md` 파일이 있으면 Codex는 그 파일을 먼저 읽습니다. 이 경우 미리보기에 경고가 나옵니다.

### 6-6. MCP 서버

MCP 서버는 AI 도구가 쓸 수 있는 외부 기능(GitHub, 브라우저, DB 등)입니다.

1. 처음에는 **반드시** `지금 쓰는 서버 가져오기`를 누르세요.
   적용하면 각 도구의 MCP 목록 **전체**가 앱의 목록으로 바뀌기 때문에, 먼저 지금 쓰는 서버를 가져와야 안전합니다.
2. `새로 만들기`로 서버를 추가합니다.
   - **연결 방식**: `stdio`(명령 실행) 또는 `http`/`sse`(URL)
   - stdio: **명령**(예: `npx`), **인자**(한 줄에 하나, 예: `-y` / `@modelcontextprotocol/server-github`), **환경변수**(`KEY=값`)
   - http: **URL**, **헤더**(`이름=값`)
3. `서버 추가` → `미리보기 후 적용`

적용 방식:

| | 전역 | 프로젝트 |
|---|---|---|
| Claude Code | 공식 명령 `claude mcp add-json … -s user`로 등록 (설정 파일을 직접 고치지 않음) | `<프로젝트>/.mcp.json`에 씀 |
| Codex CLI | `~/.codex/config.toml`의 MCP 부분만 바꿈 (다른 설정 유지) | `<프로젝트>/.codex/config.toml` |

알아 둘 점:
- 비밀값은 `••••`로 보입니다. **그대로 두고 저장하면 원래 값이 유지**됩니다. 바꾸려면 새 값을 입력하세요.
- 앱 목록에 없는 서버가 도구에 있으면 미리보기에 "적용하면 지워집니다" 경고가 나옵니다. 그럴 땐 MCP 화면 왼쪽 위 `가져오기`를 누르세요.
- **프로젝트**에 쓸 때:
  - Claude Code는 `.mcp.json`의 서버를 처음 쓸 때 사용 승인을 묻습니다.
  - Codex는 신뢰한 프로젝트에서만 `.codex/config.toml`을 읽습니다.
  - `.mcp.json`은 보통 git에 함께 올라가므로, 토큰 같은 값은 `${GITHUB_TOKEN}`처럼 환경변수 참조로 쓰는 게 좋습니다. 그대로 쓰면 미리보기에서 경고합니다.
- `startup_timeout_sec`, `enabled = false` 같은 Codex 전용 설정은 `기타 Codex 설정`으로 보이고 그대로 유지됩니다.

> ⚠️ **Claude Code 안에서 앱을 실행한 경우**(예: Claude Code 터미널에서 `npm run dev`) 전역 Claude Code MCP 변경은 막힙니다. Claude Code가 자기 세션 안에서의 등록을 거부하기 때문입니다. Finder/시작 메뉴에서 앱을 직접 여세요.

### 6-7. Claude 설정 (권한, hooks)

Claude Code `settings.json`의 권한 규칙입니다. **허용**은 묻지 않고 실행, **확인**은 항상 묻기, **거부**는 막기입니다 (거부가 확인보다, 확인이 허용보다 우선).

| | 전역 | 프로젝트 |
|---|---|---|
| Claude Code | `~/.claude/settings.json` | `<프로젝트>/.claude/settings.json` (팀과 공유) |

1. `지금 쓰는 권한으로 시작하기`를 누르면 `settings.json`의 목록을 가져옵니다.
2. 세 목록에서 규칙을 추가하거나 빼고, `템플릿에서 추가`(위험한 명령 막기, 비밀 파일 보호, push 전에 묻기, 읽기 전용 git 허용)를 쓸 수 있습니다. 템플릿은 규칙을 더하기만 하고, 이미 다른 목록에 있는 규칙은 그대로 둡니다.
3. `변경 저장` 후 `미리보기 후 적용`.

- 규칙은 `settings.json`과 같은 형식으로 씁니다: `도구` 또는 `도구(패턴)`. 예: `Bash(npm test:*)`, `Read(./.env)`, `WebFetch(domain:github.com)`, `mcp__github`.
- 바뀌는 것은 `allow`·`ask`·`deny` 목록뿐입니다. 파일의 다른 설정(model, env, hooks, `defaultMode` 등)과 파일 모양은 그대로 둡니다. 미리보기에서 `env` 값과 비밀값으로 보이는 값은 가려집니다.
- Kitroom은 관리하는 도구(Bash, Read 등)의 규칙을 통째로 바꾸고, 다른 도구의 규칙은 그대로 둡니다. 관리하는 도구의 규칙이 `settings.json`에 있는데 Kitroom 목록에 없으면(예: Claude Code에서 "다시 묻지 않기"로 추가된 규칙) 지우기 전에 미리보기에서 경고합니다.
- 가져오기는 다음 규칙을 `settings.json`에 그대로 두고 이유를 알려 줍니다: Kitroom이 다른 모양으로 다시 쓰게 되는 규칙(예: `Bash(*)`는 `Bash`로, `Write(…)`는 `Edit(…)`로), 여러 목록에 들어 있는 규칙, 그리고 이런 규칙과 같은 도구의 나머지 규칙.
- `settings.local.json`과 회사 관리 설정(managed settings)은 쓰지 않습니다.
- 지금은 Claude Code만 지원합니다. Codex 권한은 방식(샌드박스 프로필)이 달라 아직 쓰지 않습니다.

#### Hooks

hook은 Claude Code가 정해진 때에 알아서 실행하는 명령입니다: `PreToolUse`(도구 실행 전, 종료 코드 2면 막음), `PostToolUse`(도구가 성공한 뒤), `UserPromptSubmit`, `Stop`(응답을 마칠 때), `Notification`, `SessionStart` 등. 같은 `settings.json`에 들어 있습니다.

1. **Claude 설정 → Hooks**에서 `지금 쓰는 hooks로 시작하기`를 누릅니다. 지금 hooks를 그대로 가져옵니다.
2. 이벤트마다 묶음이 나옵니다: **도구**(matcher, 예: `Bash`, `Edit|Write`, 비우면 모든 도구)와 명령, 제한 시간(초, 선택). 이벤트를 골라 `hook 추가`를 누르거나 `템플릿에서 추가`(Prettier로 포맷, `rm -rf` 막기, 끝나면 알림 macOS/Linux)를 쓸 수 있습니다. 템플릿 설명에 필요한 도구(예: `jq`)가 적혀 있습니다.
3. `변경 저장` 후 `미리보기 후 적용`. 미리보기에 Claude Code가 실행하게 될 새 명령·바뀐 명령이 모두 나옵니다.

- hook은 묻지 않고 내 권한으로 명령을 실행합니다. 이해하는 명령만 넣으세요. 프로젝트의 `.claude/settings.json`은 보통 git에 올라가므로 팀원도 실행하게 되며, 미리보기에서 알려 줍니다.
- 명령은 입력한 그대로 씁니다. Kitroom이 고쳐 쓰지 않습니다.
- 편집할 수 있는 것은 명령(command) hook뿐입니다. 다른 종류(`prompt`, `agent`, `http`)와 추가 항목은 그대로 유지되고 삭제만 할 수 있습니다. 이 안의 비밀값(헤더, URL의 토큰)은 앱에서 가려집니다.
- 바뀌는 것은 `hooks` 키뿐입니다. `disableAllHooks`와 다른 설정은 그대로 둡니다.
- 지금은 Claude Code만 지원합니다. Codex hooks는 방식이 달라 아직 쓰지 않습니다.

### 6-8. 터미널

1. 오른쪽 위 `새 탭:`에서 `+ Claude Code`, `+ Codex CLI`, `+ 셸` 등을 누릅니다.
   - 회색으로 꺼진 버튼은 그 도구를 PATH에서 못 찾았다는 뜻입니다.
2. 탭은 위쪽에서 바꾸고 `×`로 닫습니다. 다른 메뉴로 갔다 와도 실행은 계속됩니다.
3. 프로젝트를 골라 두면 그 폴더에서 실행됩니다 (아래 `실행 위치:`에 표시).

단축키 (macOS는 ⌘, Windows·Linux는 Ctrl):

| 키 | 동작 |
|---|---|
| ⌘/Ctrl + F | 출력에서 찾기 (Enter 다음, Shift+Enter 이전, Esc 닫기) |
| ⌘/Ctrl + `+` / `-` | 글자 크기 키우기 / 줄이기 (저장됨) |
| ⌘/Ctrl + 0 | 기본 글자 크기 |
| Ctrl + Shift + C / V | (Windows·Linux) 복사 / 붙여넣기. 그냥 Ctrl+C는 실행 중단입니다. |

- 출력의 `https://…` 링크를 클릭하면 브라우저로 열립니다.
- 프로그램이 끝나면 아래에 `다시 실행` 버튼이 생깁니다.

- 설정은 `~/.kitroom/settings.json`에 저장됩니다.

## 8. 문제가 생겼을 때

### 앱에서 되돌리기
대부분은 `적용 기록 → 되돌리기`로 해결됩니다.
적용 후 내가 직접 고친 파일은 덮어쓰지 않고 그대로 둡니다(알림에 표시됨).

### 직접 복원하기
앱이 열리지 않는 등 되돌리기를 못 쓸 때:

- 백업 위치
  - 전역: `~/.kitroom/backups/<날짜-시각-…>/`
  - 프로젝트: `~/.kitroom/projects/<프로젝트이름-…>/backups/<날짜-시각-…>/`
- 폴더 안 `manifest.json`에 **원래 파일 경로(`path`)**와 **백업 파일 이름(`backup`, 예: `000.bak`)**이 적혀 있습니다.
  `.bak` 파일을 원래 경로로 복사하면 됩니다. `backup`이 `null`이면 앱이 새로 만든 파일이니 지우면 됩니다.
- Claude Code 전역 MCP는 터미널에서 `claude mcp list` / `claude mcp remove <이름> -s user`로 확인·삭제할 수 있습니다.

> 백업에는 MCP 토큰 같은 비밀값이 들어 있을 수 있어 본인만 읽을 수 있게 저장됩니다. 다른 사람에게 보내지 마세요.

### 앱을 완전히 지우기
1. 앱 삭제 (macOS: 응용 프로그램에서 휴지통으로 / Windows: 설정 → 앱에서 제거)
2. 앱 데이터 삭제: `~/.kitroom` 폴더
   (이미 적용한 도구 설정 파일은 남습니다. 필요하면 먼저 되돌리기를 하세요.)

### 자주 보는 메시지

| 메시지 | 뜻 / 해결 |
|---|---|
| "Claude Code 세션 안에서…" (MCP 적용이 막힘) | Claude Code 안에서 앱을 실행했습니다. 앱을 Finder/시작 메뉴에서 직접 여세요. |
| "미리보기 이후 바뀌었습니다. 다시 미리보기 하세요" | 미리보기 후에 파일이 바뀌었습니다. 미리보기를 다시 하세요. 안전장치입니다. |
| 터미널 버튼이 회색 | 그 도구를 찾지 못했습니다. 일반 터미널에서 `which claude`(Windows: `where claude`)가 되는지 확인해 주세요. |
| "이 파일은 Kitroom이 만든 것이 아닙니다" | 같은 이름의 파일이 이미 있어서 교체됩니다. 원본은 백업됩니다. |

## 9. 알려진 제한

- 코드 서명이 없어 설치 때 보안 경고가 뜹니다 (2장 참고). 업데이트는 새 버전 알림을 보고 직접 받아 설치합니다 (Homebrew로 설치했다면 `brew upgrade --cask kitroom`).
- Copilot CLI·Antigravity CLI는 **보기만** 됩니다. 설정 파일 위치는 공식 문서를 따랐고, 실제 설치로는 아직 써 보지 못했습니다.
- Claude Code MCP의 `local` 범위(특정 프로젝트에만, 공유 안 함)는 아직 지원하지 않습니다.
- 이미지 같은 텍스트가 아닌 파일이 든 스킬은 가져오지 않습니다.
